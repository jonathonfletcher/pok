/hw/nodes · /hw/pods · /hw/status · /hw/ — each visit is logged to Kafka and appears below

Live view of a Kubernetes cluster — the latest value per subject, updating in real time over a WebSocket. Two feeds: periodic cluster state, and per-URL visit counts from the helloworld app.

How the data reaches this page:

Source
A clusterinfo deployment polls the Kubernetes API every 0.5 s (one random cluster aspect per tick — nodes, pods, namespaces, deployments, services, capacity, Cilium state, and more); the helloworld app emits one event per URL it serves.
Ingest
Both publish to the in-cluster Kafka brokers (Strimzi/KRaft) — clusterinfo to cluster-info, helloworld to url-visits. A visitcounter service consumes url-visits and maintains a running per-URL total on the log-compacted visit-counts topic.
Serve
The wsfeed service consumes cluster-info and visit-counts, keeps the current value per subject, and streams updates to your browser over a WebSocket at /ws.
Sort:
Latest value per subject, updating live.
