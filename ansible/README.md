# Ansible — the node + bootstrap layer

Everything **below the Kubernetes API**: OS prep, container runtime, kubeadm
bootstrap, node storage, registry PKI, DNS generation. The **in-cluster**
services layer (Cilium, TopoLVM, registry Deployment, OTel…) is OpenTofu (`../tf/k8s`);
see `../docs/README.md` §2–3 for how the two fit together and the full recreate order.

Only `ansible.builtin` modules — no Galaxy collections. **No Docker** —
containerd + runc come from Ubuntu's own apt repos (see the [role table](#roles--grouped-by-the-playbook-that-uses-them)).

> **You normally don't run these by hand.** The top-level `../Makefile` is the supported
> entry point: `make cluster` runs `prepare` → (manual gate) → `os_prep` → `bootstrap` → `storage`
> in order, always passing `-i inventory/$(INFRA_PROVIDER)/hosts.ini`.

**Inventory is per-provider and tofu-emitted.** `tf/<provider>` writes
`inventory/<provider>/hosts.ini` (header: `GENERATED by tf/<provider> — do not edit`):
`bhyve` = 6 nodes (`k8sm1–3`/`k8sw1–3`), `aws` = 6 nodes (`cp1–3`/`w1–3`). **No
default inventory** (`ansible.cfg` sets none), so every host-touching command needs
`-i inventory/<provider>/hosts.ini` (`--syntax-check`/`ansible-lint` don't). Playbooks
and roles are provider-agnostic; all provider differences are data in
`inventory/<provider>/group_vars/all.yml` (see [capability flags](#capability-flags)).

## Playbooks — what runs, in what order, and why

`make cluster` runs 1→4 in order, pausing at the gate.

| # | Playbook | What it does | Runs on | Needs first |
|---|----------|--------------|---------|-------------|
| — | `teardown.yml` | **DESTRUCTIVE**: `kubeadm reset` + wipe cluster dirs, empty `/var/lib/registry` on the primary CP, wipe **all** `topolvm-vg` LVs (empty VG on rebuild), regenerate each node's machine-id. Guarded by `-e confirm_teardown=yes`. (`make teardown`) | all nodes | a cluster to destroy |
| 1 | `prepare.yml` | Control-node artifacts: registry CA/cert → `../registry/certs/<provider>/`, DNS fragments → `dns/` (each gated by a capability flag) | control node | inventory |
| — | *(manual gate)* | install `dns/*.k8s.zone` on the gateway; grow each bhyve `disk0` +16 GB | — | step 1 output |
| 2 | `os_prep.yml` | updates, prereq packages/kernel-modules/sysctl/swap-off, apt repos | all nodes | ssh + sudo |
| 3 | `bootstrap.yml` | Node-prep roles → `kubeadm init` (primary) → CP joins → worker joins | all nodes | 1, DNS live |
| 4 | `storage.yml` | Build `topolvm-vg`; on **bhyve only** (`manage_data_lv: true`) first grow the PV + create `ubuntu-data-lv`. aws (`manage_data_lv: false`) builds `topolvm-vg` on `/dev/nvme1n1`. | all nodes | 3, bhyve disks grown |

After these, `make services` (OpenTofu) installs Cilium — nodes stay `NotReady`
until then. Final manual gate: `make -C apps/helloworld trust` (registry CA on the
build host) before `make app`.

## `bootstrap.yml` — the one with cross-play plumbing

5 plays; the non-obvious part is how the join credentials travel:

```
Play 0  localhost   pre-flight: assert <registry CA> exists  (only when manage_registry)
Play 1  all nodes   node_identity -> kube_containerd -> kube_packages -> kube_registry_trust
Play 2  primary_cp  kubeadm init;  set_fact: join_command, certificate_key  --+
Play 3  secondary   kubeadm join --control-plane  (join_command + certificate_key) <-+
Play 4  workers     kubeadm join                  (join_command only)             <-+
```

- **Play 0** stats and asserts the per-provider CA (`kube_registry_trust_ca_src` =
  `../registry/certs/<provider>/ca.crt`) exists, but only
  `when: manage_registry` — aws self-hosts (`true`), so it runs on both.
- **Plays 3 & 4** read from `hostvars[groups['primary_cp'][0]]`: Play 3 reads both
  `join_command` **and** `certificate_key`; Play 4 (workers) reads **only** `join_command`.
- **Idempotency is per-task, not per-play.** Only `kubeadm init`
  (`when: not /etc/kubernetes/admin.conf`) and the join tasks (`when: not kubelet.conf`)
  are guarded. The kubeconfig copy, `token create`, `upload-certs`, and the `set_fact` run
  **every time** — but `token create`/`upload-certs` are `changed_when: false`, so a re-run
  re-publishes the facts without reporting changes. Safe to re-run, not a wholesale skip.

## Roles — grouped by the playbook that uses them

| Playbook | Roles (in order) |
|----------|------------------|
| `os_prep.yml` | `node_os_update`, `kube_prerequisites`, `kube_apt_repos`, `kube_cilium_cli` (opt-in) |
| `bootstrap.yml` | `node_identity`, `kube_containerd`, `kube_packages`, `kube_registry_trust` (`manage_registry`) |
| `storage.yml` | `node_data_lv` (`manage_data_lv`), `node_topolvm_vg` |
| `prepare.yml` | `kube_registry_pki` (`manage_registry`), `infra_dns_zone` (`manage_dns_zone`) |

Roles in parens are **opt-in per provider**, gated by the named [capability flag](#capability-flags).

| Role | Does |
|------|------|
| `node_os_update` | apt update + dist-upgrade + autoremove; reboots only if required **and** `allow_reboot=true` |
| `kube_prerequisites` | base packages, kernel modules (overlay, br_netfilter), sysctls (bridge-nf, ip_forward), swap off |
| `kube_apt_repos` | deb822 repos for **Kubernetes** (pkgs.k8s.io) and **Helm** (Buildkite) only — no Docker, no Cilium |
| `kube_cilium_cli` | Cilium **CLI** from GitHub (no apt repo exists); off unless `kube_cilium_cli_install=true` |
| `node_identity` | short hostname; machine-id regen for fresh clones (`node_identity_reset_machine_id=true`) |
| `kube_containerd` | `containerd` + `runc` (Ubuntu apt, pinned) + `crictl` (CRI debug CLI, from pkgs.k8s.io); minimal `config.toml` (v3 + registry `config_path`) |
| `kube_packages` | `kubelet`/`kubeadm`/`kubectl` pinned + held; enables kubelet |
| `kube_registry_trust` | drops the registry CA + `hosts.toml` under containerd `certs.d`; asserts `config_path` is set |
| `node_data_lv` | growpart the PV -> `pvresize` -> `lvcreate ubuntu-data-lv` (leaves a free-space guard) |
| `node_topolvm_vg` | builds `topolvm-vg` on the backing device — **bhyve:** nested on `ubuntu-data-lv` (`scan_lvs=1`); **aws:** the whole `/dev/nvme1n1`. No-op if that device is absent (e.g. an aws control-plane) |
| `kube_registry_pki` | openssl-generates the registry CA + TLS cert into `../registry/certs/<provider>/` (idempotent via `creates:`) |
| `infra_dns_zone` | renders forward + reverse BIND `$INCLUDE` fragments from the inventory into `dns/` |

## Cross-role data flow (couplings not obvious from one file)

```
kube_registry_pki --> ../registry/certs/<provider>/ca.crt --> kube_registry_trust (copies to each node's certs.d)
               \-> ../registry/certs/<provider>/tls.*   --> ../tf/k8s/registry.tf (registry-tls Secret)

kube_containerd --> /etc/containerd/config.toml (config_path=/etc/containerd/certs.d)
           \-> kube_registry_trust asserts that config_path is present (else fails)

node_data_lv --> ubuntu-data-lv --> node_topolvm_vg --> topolvm-vg --> ../tf/k8s/topolvm.tf (CSI capacity)

infra_dns_zone --> dns/*.k8s.zone --> [MANUAL] $INCLUDE on gateway.homelab.lan --> bootstrap needs it live
```

## Capability flags

Roles/tasks are toggled per provider by booleans in
`inventory/<provider>/group_vars/all.yml`. `bhyve` sets all three `true`; `aws` differs.

| Flag | Gates (roles) | bhyve | aws |
|------|---------------|-------|-----|
| `manage_registry` | `kube_registry_pki`, `kube_registry_trust`, Play 0 pre-flight | `true` | `true` (self-hosted on `cp1`, no ECR) |
| `manage_dns_zone` | `infra_dns_zone` | `true` | `false` (Route 53 / VPC DNS) |
| `manage_data_lv` | `node_data_lv` | `true` | `false` (dedicated `nvme1n1` disk) |

## Setup (isolated Python venv)

```bash
cd ansible
sudo apt-get install -y python3-venv          # once, if venv creation fails
python3 -m venv .venv
./.venv/bin/pip install -U pip
./.venv/bin/pip install -r requirements.txt   # ansible-core + ansible-lint (pinned)
source .venv/bin/activate                      # then use ansible* directly
```

`.venv/` is gitignored; `requirements.txt` pins ansible-core 2.21.2, ansible-lint 26.6.0.

## Run

No default inventory — node-touching commands need
`-i inventory/<provider>/hosts.ini` (`bhyve`|`aws`); `--syntax-check`/`ansible-lint` don't.

```bash
P=inventory/aws/hosts.ini                            # or inventory/bhyve/hosts.ini
ansible -i $P -m ping kube_cluster                   # connectivity (ssh + sudo)
ansible-playbook --syntax-check bootstrap.yml        # static validation (no -i needed)
ansible-lint                                          # lint (passes 'production' profile)
ansible-playbook -i $P os_prep.yml --check                    # dry run, no changes
ansible-playbook -i $P os_prep.yml                            # OS prep, all nodes
ansible-playbook -i $P os_prep.yml --tags kube_apt_repos      # just the repos
ansible-playbook -i $P teardown.yml -e confirm_teardown=yes   # DESTRUCTIVE teardown
ansible-playbook -i $P bootstrap.yml                          # init + joins
ansible-playbook -i $P os_prep.yml -e kube_cilium_cli_install=true --tags kube_cilium_cli
```

`python3-debian` (installed by `kube_prerequisites`) is needed by `kube_apt_repos`'s
`deb822_repository` module; the role order in `os_prep.yml` handles that.

## Notes

- **No Docker anywhere** — containerd/runc come from Ubuntu apt (`noble-updates`),
  installed conventionally (`/usr/bin`, the package's own unit). Never add a Docker repo.
- **Reboots default OFF** (`allow_reboot=false`) — reboot-requiring OS upgrades should be rolling.
- **Cilium has no apt repo** — deployed by OpenTofu/Helm; only the CLI is an Ansible role.
- **Validated:** `--syntax-check` and `ansible-lint` (production profile) pass. Lint is
  static — still `--check` against the fleet before a real apply.
